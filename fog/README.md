# `fog/` — Fog Layer (Ingestion, Inference, Dashboard)

## Purpose

Implements the fog computing layer. This layer runs on a local machine (e.g., a PC on the same network as the ESP32 edge device). It is responsible for:

1. Subscribing to the MQTT broker to receive vitals streamed from the edge layer.
2. Validating incoming readings with physiological sanity checks.
3. Persisting all readings (valid and invalid) to a local SQLite database.
4. Running real-time anomaly detection inference using a pre-trained LSTM Autoencoder.
5. Serving a live monitoring dashboard via Streamlit.

## Subdirectories & Key Files

### `ingestion/`

- **`mqtt_subscriber.py`** — Core ingestion service. Connects to `broker.hivemq.com` via `paho-mqtt` (MQTTv5). On each incoming vitals message:
  1. Parses JSON payload.
  2. Applies physiological sanity checks (HR: 30–220 bpm; SpO2: 70–100%).
  3. Writes the reading to `data/patient_vitals.db` with a `passed_sanity` flag.
  - Also creates the `vitals` and `anomaly_alerts` SQLite tables on startup if they do not exist.
  - Logs all activity to console and `ingestion.log`.
  - Run: `python mqtt_subscriber.py`

- **`db_viewer.py`** — Utility script to inspect the most recent readings stored in SQLite. Accepts an optional command-line argument for the number of rows to display (default: 20).
  - Run: `python db_viewer.py [N]`

- **`ingestion.log`** — Log file generated by `mqtt_subscriber.py`.

### `model/`

- **`inference.py`** — Loads the trained LSTM Autoencoder model (`model.keras`) and scaler (`scaler.pkl`) from `models/lstm_autoencoder/`. Fetches the latest 60-sample window of valid readings from SQLite, normalises them with the training scaler, runs model inference, and returns the reconstruction error (MSE) for the window.

- **`anomaly_detector.py`** — Standalone background loop that periodically (every 5 seconds) invokes `inference.py`. Compares the reconstruction error against a p95 threshold (medium severity) and a p99 threshold (high severity). Writes alert records to the `anomaly_alerts` table in SQLite. Prevents duplicate alerts for the same reading. Logs all decisions to `anomaly_detector.log`.
  - Run: `python anomaly_detector.py`

### `dashboard/`

- **`app.py`** — Streamlit web dashboard. Auto-refreshes every 5 seconds via `streamlit-autorefresh`. Displays:
  1. Live vitals cards (Heart Rate, SpO2, last reading timestamp) with clinical status indicators (Normal/Bradycardia/Tachycardia, Normal/Low/Critical).
  2. Time-series charts for HR and SpO2 (last 200 readings) with clinical threshold bands.
  3. Anomaly score chart with p95/p99 threshold lines.
  4. Alert log table with severity badges.
  5. Footer with total reading and alert counts.
  - Run: `streamlit run app.py`

### `patient_vitals.db`

SQLite database file generated at runtime. Contains the `vitals` and `anomaly_alerts` tables.

### `anomaly_detector.log`

Log file generated by `anomaly_detector.py`.
